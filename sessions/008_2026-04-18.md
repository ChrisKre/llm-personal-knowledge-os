**P2 — graph_reader Phase 1 → Tag-Overlap-Scoring**

Aktuell: freies Keyword-Matching auf index.md-Text.
Ziel: Tags aus index.md-Einträgen extrahieren, Tag-Overlap mit Query-Keywords berechnen.

```python
def _search_index_md(query: str, type_filter: str | None, limit: int) -> list[WikiPage]:
    keywords = set(_extract_keywords(query))  # Haiku
    entries = _parse_index_entries()
    
    scored = []
    for entry in entries:
        if type_filter and entry.type != type_filter:
            continue
        overlap = len(keywords & set(entry.tags)) / max(len(keywords), 1)
        if overlap > 0:
            scored.append((overlap, entry))
    
    scored.sort(reverse=True)
    return [_load_page(e.slug) for _, e in scored[:limit]]
```

SQLite-Threshold: von 150 auf 30 senken in `graph_reader.py`.

## Kernkonzepte (Wiederholung für neues Claude-Fenster)

**Graph Context Match:** Vor jeder Agent-Ausführung: Top-N relevante Wiki-Seiten für den Input laden. Agenten bewerten nie isoliert. Qualität hängt von graph_reader ab — daher P2 kritisch.

**Zwei State-Ebenen:**
- `user_profile.md` (~80-120 Zeilen) — immer im Kontext, statisch
- `graph_context` — dynamisch, per-Task, Top-N Wiki-Seiten

**WikiWrite-Vertrag:** Kein Agent schreibt direkt Dateien. Alle schreiben WikiWrite-Objekte → graph_writer führt nach Supervisor-Freigabe aus.

**Draft→Main Workflow:** LLM schreibt auf draft-Branch, Nutzer gibt via Telegram frei. In MVP-0/1 noch nicht aktiv — direkt auf main schreiben.

**Audio-API-Bug:** Claude verarbeitet kein Audio. Story-Lab V1 gibt nur Timing-Feedback (Whisper) + Transkript-Strukturanalyse (Sonnet auf Text). Tonal-Qualität (Enthusiasmus, Natürlichkeit) erst wenn Audio-API existiert oder alternative Pipeline gefunden wird.
