```python
    "source_type": "text",
    "content": "Ich war heute beim ersten Flamenco-Kurs. Der Lehrer schaute mich an und sagte: 'Du denkst noch. Hör auf zu denken.'",
    "user_hint": "bootstrap",
    "processed": False,
    "wiki_refs": [],

```
Voraussetzungen: `.env` mit `ANTHROPIC_API_KEY` anlegen.

**2. LanguageAgent cultural_entry country-Code:**
In `write_entries()` ist der CulturalEntry-Pfad hardcoded als `c_es_[slug].md`. Für nicht-spanische Entitäten (englische Bücher, deutsche Orte) ist das falsch. Fix: Land aus Inhalt oder `entity_type` ableiten, oder als `c_intl_[slug].md` fallback.

**3. _update_index() Zähler-Bug bei gleichzeitigen Writes:**
Wenn mehrere Writes in denselben Abschnitt gehen (z.B. 3 VocabEntries auf einmal), werden die Zähler korrekt addiert — aber der Regex-Such-Index kann nach dem ersten Ersetzen verschieben. Testen mit Mehrfach-Writes.

**4. LintAgent _apply_auto_fixes() ist Stub:**
Die Auto-Fix-Logik (missing_backlink, anki_gap, orphan) ist implementiert als `pass`. In Session 007 mindestens `anki_gap` implementieren: AnkiConnect aufrufen wenn Anki läuft, sonst Task in raw/events/.

**5. detect_words() heuristisch:**
`_extract_cultural_entity()` in language_agent.py nutzt eine kleine Hard-coded-Trigger-Liste. Wenn der Nutzer von "Flamenco" schreibt, wird der CulturalEntry erstellt. Wenn er aber von "zapateado" oder "compás" schreibt ohne "Flamenco" zu erwähnen, passiert nichts. Langfristig: Haiku-Klassifikation für CulturalEntry-Trigger statt Keyword-Liste.

## Kernkonzepte (Wiederholung für neues Claude-Fenster)

**Graph Context Match:** Vor jeder Agenten-Ausführung werden Top-N relevante Wiki-Seiten für den aktuellen Input geladen (`graph_context`). Agenten bewerten nie isoliert.

**Zwei State-Ebenen:**
- `user_profile.md` (~80-120 Zeilen) — komprimierte Nutzer-Signatur, immer im Kontext
- `graph_context` — dynamisch per Task, konkret relevante Wiki-Seiten

**Draft→Main Workflow:** LLM schreibt immer auf `draft`-Branch. Kritische Änderungen brauchen Nutzer-Freigabe via Telegram-Button → Python `git merge`.

**WikiWrite-Vertrag:** Kein Agent schreibt direkt Dateien. Alle schreiben WikiWrite-Objekte in den State. graph_writer führt nach Supervisor-Freigabe aus.

**Ingest-Reihenfolge:**
```
bot.py → Extractor → raw/events/ → main_workflow.run_ingest()
  → classify → fetch_graph_context → [diary_agent | language_agent]
  → supervisor_review → write_to_graph → update_index
```

**Services-Architektur (GE-001, noch nicht implementiert):**
- ServiceDefinition = Wiki-Seite in wiki/personal/services/sd_[slug].md
- Generischer ServiceConversationHandler(ServiceDefinition)
- StyleProfile-Anreicherung via context_profiles-Map
- Meta-Routine = Option B (Template-Instanziierung)
- Max. 5 aktive Services; erster Service = Crypto (manuell, ohne Meta-Routing)
