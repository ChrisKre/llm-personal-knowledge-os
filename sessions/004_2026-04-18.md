**2. GE-001 Branch — merge-Zeitpunkt:**
`COMP_SERVICES.md` liegt auf `experiment/ge-001-services-meta-routine`. Die Datei soll nach `master` wenn der erste echte Service implementiert werden soll (frühestens nach Bootstrap + Core-Pipeline). Jetzt noch nicht mergen — zuerst Infrastruktur auf master fertigstellen.

**3. Services sind Schritt 3, nicht Schritt 1:**
Der häufigste Fehler wäre, Services zu früh zu bauen. Dependency-Reihenfolge einhalten:
```
requirements.txt + main_workflow.py   →   bot.py Grundgerüst
    →   Bootstrap-Interview lauffähig  →   Core-Pipeline (diary + language)
    →   Lint-Agent implementiert       →   DANN: erster Service
```
Services ohne lauffähige Core-Pipeline sind wertlos — kein Graph-Inhalt = kein Service-Stimulus.

**4. Crypto-Service Stimulus-Bibliothek:**
Für den ersten Service braucht es ~15–20 Candlestick-Pattern-PNGs in `raw/assets/crypto_charts/`. Das ist manuelle Arbeit — muss vom Nutzer vorbereitet werden, kein Agent-Task. Frühzeitig erwähnen.

## Kernkonzepte (Wiederholung für neues Claude-Fenster)

**Graph Context Match:** Vor jeder Agenten-Ausführung werden Top-N relevante Wiki-Seiten für den aktuellen Input geladen (`graph_context`). Agenten bewerten nie isoliert.

**Zwei State-Ebenen:**
- `user_profile.md` (~80-120 Zeilen) — komprimierte Nutzer-Signatur, immer im Kontext
- `graph_context` — dynamisch per Task, konkret relevante Wiki-Seiten

**Draft→Main Workflow:** LLM schreibt immer auf `draft`-Branch. Kritische Änderungen brauchen Nutzer-Freigabe via Telegram-Button → Python `git merge`.

**WikiWrite-Vertrag:** Kein Agent schreibt direkt Dateien. Alle schreiben WikiWrite-Objekte in den State. graph_writer führt nach Supervisor-Freigabe aus.

**Services-Architektur (GE-001):**
- ServiceDefinition = Wiki-Seite in `wiki/personal/services/sd_[slug].md`
- Generischer `ServiceConversationHandler(ServiceDefinition)` — nicht ein Handler pro Service
- StyleProfile-Anreicherung via `context_profiles`-Map — additive, kein Schema-Bruch
- Meta-Routine = Option B (Template-Instanziierung), Nutzer-Bestätigung immer nötig
- Max. 5 aktive Services; erster Service = Crypto-Service manuell (ohne Meta-Routing)
