## Architektonische Bedenken (vom Architect aus Session 005)

**1. Erster Ingest-Test ist oberste Priorität:**
Alle Kernkomponenten existieren jetzt. Session 006 sollte mit einem manuellen End-to-End-Test beginnen:
```python
from main_workflow import run_ingest
result = run_ingest({
    "source": "manual",
    "source_type": "text",
    "content": "Ich war heute beim ersten Flamenco-Kurs. Der Lehrer schaute mich an und sagte: 'Du denkst noch. Hör auf zu denken.'",
    "user_hint": "bootstrap",
    "processed": False,
    "wiki_refs": [],
})
```
Vor dem Test: `wiki/` Verzeichnis + `index.md` + `user_profile.md` anlegen (sonst Fehler).

**2. First-Run-Setup fehlt:**
`wiki/`, `index.md`, `log.md`, `user_profile.md` werden nirgendwo initialisiert. Bot und Workflow crashen ohne sie. Vor echtem Test: Init-Skript oder manuell anlegen.

**3. diary_agent._parse_kv() — LLM-Format-Fragility:**
LLMs halten sich nicht immer strikt an das definierte Format. `_parse_kv()` ist best-effort. Fallback ist immer 0 für numeric fields. Beobachten ob echte Prompts gut parsen — ggf. JSON-Output-Format nachträglich erwägen.

**4. `both`-Intent vereinfacht:**
main_workflow mappt "both" → diary_agent. Wenn Language-Agent implementiert wird, muss dieser Pfad auf Parallelverarbeitung umgestellt werden (LangGraph `Send()`-API).

**5. TELEGRAM_BOT_TOKEN + ANTHROPIC_API_KEY in .env:**
`.env`-Datei muss vor dem Start angelegt werden. Format:
```
ANTHROPIC_API_KEY=sk-ant-...
TELEGRAM_BOT_TOKEN=123456789:...
```
`.env` ist nicht im Git-Repo (nicht committed, sensitiv).

## Kernkonzepte (Wiederholung für neues Claude-Fenster)

**Graph Context Match:** Vor jeder Agenten-Ausführung werden Top-N relevante Wiki-Seiten für den aktuellen Input geladen (`graph_context`). Agenten bewerten nie isoliert.

**Zwei State-Ebenen:**
- `user_profile.md` (~80-120 Zeilen) — komprimierte Nutzer-Signatur, immer im Kontext
- `graph_context` — dynamisch per Task, konkret relevante Wiki-Seiten

**Draft→Main Workflow:** LLM schreibt immer auf `draft`-Branch. Kritische Änderungen brauchen Nutzer-Freigabe via Telegram-Button → Python `git merge`.

**WikiWrite-Vertrag:** Kein Agent schreibt direkt Dateien. Alle schreiben WikiWrite-Objekte in den State. graph_writer führt nach Supervisor-Freigabe aus.

**Ingest-Reihenfolge:**
```
bot.py → Extractor → raw/events/ → main_workflow.run_ingest()
  → classify → fetch_graph_context → diary_agent
  → supervisor_review → write_to_graph → update_index
```

**Services-Architektur (GE-001, noch nicht implementiert):**
- ServiceDefinition = Wiki-Seite in wiki/personal/services/sd_[slug].md
- Generischer ServiceConversationHandler(ServiceDefinition)
- StyleProfile-Anreicherung via context_profiles-Map
- Meta-Routine = Option B (Template-Instanziierung)
- Max. 5 aktive Services; erster Service = Crypto (manuell, ohne Meta-Routing)
