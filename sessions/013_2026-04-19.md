### Phase 5 im Detail — das Coding-Paket für Session 013

**Artefakt:** [bot.py](../bot.py) (244 Zeilen, Stand S005).

**Problem 1 — Kein Single-User-Filter.** [bot.py](../bot.py) hat fünf Handler (`handle_text`, `handle_voice`, `handle_photo`, `handle_document`, `handle_video`) plus den `ConversationHandler` für `/bootstrap`. Keiner prüft `update.effective_user.id`. Ein Fremder, der den Bot-Token errät oder mit dem Bot-Handle interagiert, könnte unser Wiki füttern.

**Fix:**
```python
# .env — neue Variable
TELEGRAM_ALLOWED_USER_ID=<PO-Telegram-ID>

# bot.py — globaler Decorator oder Helper
def _require_allowed_user(func):
    async def wrapper(update, context, *args, **kwargs):
        allowed = int(os.environ["TELEGRAM_ALLOWED_USER_ID"])
        if update.effective_user.id != allowed:
            logger.warning("rejected user %s", update.effective_user.id)
            return
        return await func(update, context, *args, **kwargs)
    return wrapper
```
Auf alle fünf normalen Handler UND `bootstrap_start` anwenden.

**Bootstrap-Discovery:** Wenn User-ID noch unbekannt, Bot einmal ohne Filter starten, eigene Nachricht an den Bot schicken, ID aus dem Log ablesen, dann `.env` befüllen und Filter aktivieren. Das ist eine Einmal-Aktion.

**Problem 2 — Kein globaler Error-Handler.** Die individuellen Handler haben zwar `try/except` um `_process_and_reply` ([bot.py:95-97](../bot.py#L95-L97)), aber Exceptions innerhalb der Telegram-Library (Netz-Drops, API-Errors) killen das Polling stumm. Siehe [hinweise/technischer_hinweis.md §3](../hinweise/technischer_hinweis.md): "bot.py kein Error-Handling".

**Fix:**
```python
async def _global_error_handler(update, context):
    logger.error("uncaught: %s", context.error, exc_info=context.error)
    if update and update.message:
        try:
            await update.message.reply_text(f"Systemfehler. Log geprüft.")
        except Exception:
            pass

# in main(), vor run_polling:
app.add_error_handler(_global_error_handler)
```

**Problem 3 — `ANTHROPIC_API_KEY` wird im Module-Scope gelesen** ([bot.py:41](../bot.py#L41)): `_client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])`. Ohne Key crasht `bot.py` beim Import, noch vor dem Polling-Start. Das widerspricht der Provider-Auto-Selection in [base_agent.py:39-48](../agents/base_agent.py#L39-L48) und [main_workflow.py:192-201](../main_workflow.py#L192-L201).

**Fix:**
```python
_api_key = os.environ.get("ANTHROPIC_API_KEY", "")
_client = anthropic.Anthropic(api_key=_api_key) if _api_key else None
_extractor = Extractor(wiki_root=WIKI_ROOT, anthropic_client=_client)
```
Damit läuft `bot.py` bereits im Ollama-Modus. Das ist auch die Voraussetzung dafür, dass Phase 5 überhaupt OHNE Key getestet werden kann (Bot startet, empfängt, Pipeline ollama-gefallbackt).

**Problem 4 — `drop_pending_updates=True` bei Restart**. [bot.py:239](../bot.py#L239) verwirft beim Restart aufgestaute Nachrichten. Für Dev OK, für Prod fragwürdig. Entscheidung: für MVP-1 unverändert lassen, in Session 013 notieren als MVP-2-Kandidat.
